# EmuCore — Game Boy / Game Boy Color / Game Boy Advance Emulator

Веб-эмулятор **Game Boy**, **Game Boy Color** и **Game Boy Advance**, написанный на **TypeScript** с нуля, без готовых эмуляционных ядер. Работает прямо в браузере на базе **Vite** и рендерит изображение в `<canvas>` с чёткими пикселями (160×144 для GB, 240×160 для GBA).

## Возможности

### Game Boy / Game Boy Color
- 🖥️ **CPU (SM83)** — табличный интерпретатор: все 256 основных и 256 CB-опкодов декодируются один раз при загрузке модуля в таблицу обработчиков (никакого `switch` в горячем цикле), флаги считаются через предвычисленные таблицы
- 🎨 **PPU** — режимы DMG и CGB, палитры, окно, спрайты, HBlank DMA
- 🔊 **APU** — звук через `AudioWorklet` (4 канала, стерео, 44100 Гц)
- 💾 **Картриджи**: `.gb`/`.gbc`, MBC1/MBC3/MBC5
- ⏪ **Сейв-стейты** в памяти, экспорт/импорт в файл (`.gbstate`, CRC-контроль)
- ⏩ **Двойная скорость** (CGB double speed)

### Game Boy Advance
- 🖥️ **CPU (ARM7TDMI)** — ARMv4T: полный набор ARM и Thumb инструкций, банки регистров (FIQ/IRQ/SVC/ABT/UND), исключения, CPSR/SPSR, 64-битные умножения. ARM-опкоды классифицируются в 1024-элементную таблицу диспетчеризации, Thumb — в 256-элементную
- 🧠 **Память**: 16 МБ ROM (с зеркалированием), 256 КБ EWRAM, 32 КБ IWRAM, I/O, палитра, 96 КБ VRAM, OAM, SRAM/Flash
- 🎨 **PPU**: режимы 0–5 (tile и bitmap), аффинные фоны, текстовые фоны, спрайты (включая аффинные), окна WIN0/WIN1/OBJWIN, alpha blending и brightness-эффекты
- ⏱ **Таймеры, DMA** (4 канала: immediate/VBlank/HBlank) и контроллер прерываний
- 📼 **BIOS (HLE)**: SWI-вызовы Div/Sqrt/ArcTan/CpuSet/LZ77/RL/BitUnpack/affine-преобразования, IntrWait/VBlankIntrWait и диспетчеризация IRQ через пользовательский обработчик
- 💾 **Сохранения**: SRAM и Flash (определяются по маркерам в ROM), сейв-стейты (`.gbastate`)
- ⌨️ **Ввод**: D-Pad, A, B, L, R, Start, Select

## Управление

| Клавиша | Game Boy | Game Boy Advance |
|---------|----------|------------------|
| Стрелки | D-Pad | D-Pad |
| `Z` | A | A |
| `X` | B | B |
| `A` | — | L |
| `S` | — | R |
| `Enter` | Start | Start |
| `Backspace` | Select | Select |
| `F5` / `F6` | Сейв-стейт / загрузка | Сейв-стейт / загрузка |

Тип ядра выбирается автоматически: по расширению `.gba` или по сигнатуре заголовка GBA-картриджа (`0xB2 == 0x96`). Игра автоматически стартует после нажатия **Start** или любой клавиши управления.

## Тесты

```bash
npm test
```

Набор покрывает CPU (SM83 и ARM7TDMI, включая Thumb, флаги, ветвления, 64-битные умножения), APU, геймпад, сейв-стейты, скорость CGB, PPU Game Boy Advance (tile/bitmap/спрайты), карту памяти GBA, таймеры, DMA и SWI-функции BIOS.

> Часть тестов (`cgb-speed`, `capture`) использует ROM-файлы из каталога `rom/`, который не входит в репозиторий.

### Принципы CPU-ядер

Вместо одного большого `switch` по опкодам используются:

1. **Декодирование один раз.** Все опкоды раскладываются в таблицы обработчиков на этапе инициализации модуля; таблицы общие для всех экземпляров машин.
2. **Диспетчеризация по таблице.** Горячий цикл — чтение опкода, индексный доступ к таблице и вызов обработчика. ARM-инструкции индексируются по битам 27–20 (256 ячеек), Thumb — по битам 15–8; поля операндов (регистр/непосредственное значение, умножение против обработки данных) разбираются внутри обработчика и не влияют на выбор ячейки.
3. **Табличные флаги.** SM83 считает флаги сложения/вычитания/инкремента через предвычисленные `Uint8Array`-таблицы.
4. **Разделение шины и CPU.** ARM-ядро общается с машиной через интерфейс `ArmBus`/`ArmHooks`, а не через прямые ссылки на PPU/DMA — ядро можно тестировать отдельно.
5. **Событийная синхронизация.** PPU и таймеры получают точное число циклов; HBlank/VBlank-события запускают DMA и IRQ. Остановленный (`HALT`) CPU не прокручивается по одному циклу, а пропускает время скачками до пробуждения.

## Ограничения GBA-ядра

- Звук GBA пока не эмулируется (регистры сохраняются, но выход — тишина).
- EEPROM-сохранения определяются, но не реализованы (последовательный протокол); SRAM/Flash работают. RTC и GPIO не поддерживаются.
- Тайминги памяти приближённые (без учёта WAITCNT и prefetch-буфера), мозаика не реализована.
